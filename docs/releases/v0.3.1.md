# HookBuoy v0.3.1

Maintenance patch focused on everyday CLI usability. No changes to Circle webhook signing, synthetic fixture formats, HTTP delivery policy or byte-exact replay.

## Changes

- Simplified the interactive menu and its response display: shorter event IDs, HTTP status and latency, saved-delivery hint, and concise synthetic-data warning.
- Interactive **3 — Bad signature** selects a Gateway fixture for `arc-fintech` or an explicit local Gateway endpoint; Wallets remains the default elsewhere.
- Interactive **2 — Replay last** remembers the expected HTTP status of the last saved send (including 403 for a deliberately invalid request), even after reopening the CLI. This prevents a correct 403 response from appearing as a failure.
- **6 — Initialize** now identifies an already configured project rather than attempting to overwrite its setup.
- Existing project configurations remain readable. The optional last expected status is validated before use.
- Added regression coverage for menu mapping, saved replay expectations, and existing project compatibility.

## Install

Requires Node.js 22+:

```sh
npm install --global hookbuoy@0.3.1
hookbuoy --version
hookbuoy
```

## Compatibility

Non-interactive commands retain their existing output and exit-code behavior: `hookbuoy replay last` still expects HTTP 2xx by default unless `--expect-status` is explicitly provided. The new expectation memory applies **only to the numbered interactive replay shortcut**.

Wallets and Gateway local E2E compatibility was established in the v0.3.0 series. No real Circle transfers, production keys or on-chain settlement are involved.

See [CLI guide](../cli.md), [Gateway E2E evidence](../pilots/arc-fintech-gateway-v0.3-actions.md) and [publishing guide](../npm-publishing.md).
