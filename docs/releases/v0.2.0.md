# HookBuoy v0.2.0

Second source release. Focus: shorter everyday CLI workflows and repeatable local webhook verification, without adding a server, SDK or dependencies.

## What's new

- `hookbuoy init` / `hookbuoy init arc-commerce`: local test keys and project endpoint, with no overwrites.
- `hookbuoy status` and `hookbuoy events`: inspect configuration and available synthetic scenarios.
- Short fixture aliases: `inbound.complete` and `inbound.failed`; the original `wallets.inbound.*` aliases still work.
- Configured `send` automatically stores an immutable signed request in `.hookbuoy/deliveries/`; `hookbuoy replay last` preserves request bytes/signature.
- Bare `hookbuoy` opens a simple numbered terminal menu when a TTY is attached. Non-TTY execution remains non-interactive.
- `hookbuoy check signature`, `hookbuoy check body` and `send --fault signature|body` validate rejection of deliberately invalid requests (default expected HTTP 403).
- 25 automated tests; Node.js 22/24 CI and installed-package tarball smoke-test.
- An [Arc Commerce local E2E runner](../arc-commerce-e2e.md), with [author-reported PASS evidence](../pilots/arc-commerce-v0.2-local.md) against pinned upstream revision and local Supabase.

## Build from source

Requires Node.js 22+, npm and Git:

```sh
git clone https://github.com/NothernZhongKui/hookbuoy.git
cd hookbuoy
git checkout v0.2.0
npm ci
npm run build
node dist/src/cli.js --help
```

The npm package has **not** been published; do not use `npm install hookbuoy` until an npm release is announced.

## Boundaries

HookBuoy sends synthetic Circle Wallets-shaped notifications signed by a dedicated **local test key**, not Circle. Never enable local test-key trust in production. HTTP results alone do not demonstrate settlement or business-state correctness. The Arc Commerce pilot used a disposable local database and does not establish real Circle delivery, USDC transfer or network settlement. MIT licensed.
